# 0007 — Общий приоритет OCR для Telegram и MAX

## Context

Telegram и MAX должны выполнять одинаковый OCR-маршрут. Для обеих служб требуется OpenRouter первым, затем локальный модуль rupasportread, чтобы локальный OCR мог дополнять отсутствующие поля. Общий OpenRouter ключ уже поступает из .env, который читают оба бота. При этом сервер может использовать прежний MAX_OCR_MODULE_PRIORITY.

## Decision

Задать общий приоритет OCR через BOT_OCR_MODULE_PRIORITY. Если он не задан, сохранить совместимость с MAX_OCR_MODULE_PRIORITY; если не задан и он, использовать openrouter,rupasportread. Оба бота используют общий OpenRouter ключ. Удалить Telegram-only пустое значение, которое перекрывало общий ключ.

## Why

Общий порядок openrouter,rupasportread даёт Telegram и MAX один hybrid pipeline: OpenRouter распознаёт документ первым, а локальный модуль дополняет отсутствующие поля.

Раздельные приоритеты для мессенджеров отклонены, потому что оставили бы разницу в распознавании. Обязательная настройка только новой переменной BOT_OCR_MODULE_PRIORITY без fallback отклонена, потому что потребовала бы повторно настраивать существующий .env и не сохранила бы совместимость с MAX_OCR_MODULE_PRIORITY.

## Consequences

Оба контейнера получают одинаковый OCR_MODULE_PRIORITY и общий ключ. Существующая конфигурация MAX продолжает работать через fallback. В логах можно показывать только безопасный статус настройки ключа, но не его значение.
