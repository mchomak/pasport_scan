# ADR 0004: Изолировать MAX SDK от скачивания media

## Context

MAX SDK-сессия используется для API MAX и по умолчанию несёт заголовок `Authorization`. URL изображения приходит из attachment payload и может указывать на произвольный HTTP(S)-хост. Передача такого URL через SDK-сессию может раскрыть токен внешнему хосту и превратить загрузку вложений в SSRF-риск. Одновременно скачивание должно оставаться ограниченным по времени и размеру и не записывать MAX-изображения на диск.

## Decision

MAX API-запросы выполняются через переиспользуемую сессию `maxapi.Bot`, а скачивание изображений — через одну отдельно управляемую неаутентифицированную async HTTP-сессию на процесс. Для загрузки применяются таймаут 30 секунд, проверка допустимого URL и HTTP-статуса, предварительная проверка `Content-Length` и потоковый лимит `OCR_MAX_FILE_MB` с остановкой после `limit + 1` байт. Полный URL, содержимое изображения и секреты не логируются. Сессия загрузок закрывается при завершении MAX-процесса; байты живут только в памяти.

## Why

Разделение сессий гарантирует, что Authorization MAX не попадёт на произвольный media-хост, а ограничение размера и времени уменьшает риск SSRF-обходов, зависаний и исчерпания памяти. Единая сессия сохраняет управляемый lifecycle без создания клиента на каждое сообщение.

## Consequences

Появляется отдельный lifecycle для media HTTP-клиента и отдельная обработка ошибок URL, статуса, timeout, пустого ответа и превышения лимита. Реализация должна тестировать отсутствие Authorization в media-запросах и гарантировать закрытие обеих сессий. Существующее временное файловое поведение Telegram/web не меняется; новые временные файлы для MAX не вводятся.
