# 0008 — Метаданные OCR в существующем JSONB

## Context

Сопровождающим нужно видеть для каждой новой успешно сохранённой записи, какие OCR-модули запускались и какой модуль предоставил каждое поле. Для вычисленного значения источник может быть отмечен как inferred.

## Decision

Сохранять modules_used и field_providers в существующем JSONB поле raw_payload новых записей. Список modules_used сохраняет порядок приоритета; field_providers содержит имя модуля или inferred. Не сохранять сырой OCR-текст, исходные ответы OpenRouter или полный ответ провайдера. Схему базы не менять и старые записи не дополнять.

## Why

Использование имеющегося JSONB поля позволяет добавить две диагностические метки без изменения схемы и миграции. Для старых записей источник полей восстановить нельзя, поэтому их обратное заполнение отклонено. Сохранение сырого текста или полного ответа провайдера отклонено: для диагностики достаточно имён модулей и поставщиков полей, а исходные ответы и распознанные строки не должны попадать в базу.

Добавление отдельных столбцов или миграции отклонено, поскольку нужные метаданные помещаются в существующее JSONB поле.

## Consequences

Новые записи содержат сведения о порядке запущенных модулей и происхождении полей; исторические записи остаются без этих сведений. Диагностические данные не содержат сырого OCR/API payload или данных изображения.
