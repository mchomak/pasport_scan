# 04 — Инициализационные логи MAX

**Требования:** R03, R05
**Blocked by:** 03
**Зона:** `bot/max_main.py`
**Волна:** 2
**Status:** ready

## Что должно заработать

MAX настраивает общий структурный логгер до проверки enabled/token и пишет безопасную инициализацию с `messenger=max`. После завершения остальных задач приложение остаётся готовым к проверке и выпуску из `main`.

## Из брифа, дословно

> «Добавить безопасные логи инициализации в обоих ботах с подписью через какой мессенджер бот работает (откуда логи)»
> «скорректируй код, коммит и пуш в main затем задеплой на сервер»

## Разделы спецификации

«Решение» 5–6; истории R03 и R05.

## Критерии приёмки

- [ ] MAX вызывает общий `setup_logger` с `messenger_source="max"` до старта polling.
- [ ] Сообщения MAX содержат `messenger=max`, включая сообщение о disabled состоянии.
- [ ] Безопасная диагностика не включает токены, API-ключи, распознанные поля или сырой provider response.
- [ ] В `ocr_modules` попадают только известные имена `openrouter`, `yandex_ocr`, `rupasportread`; произвольные значения окружения не логируются.
- [ ] MAX продолжает использовать общий runtime и прежний корректный shutdown SDK-сессии.
- [ ] Изменённый Python-файл проходит `python -m py_compile`.
- [ ] После интеграции всех задач код будет закоммичен в `main`, отправлен в `origin/main` и развёрнут на сервере; эксплуатационная проверка сверяет оба процесса и здоровье PostgreSQL.

## Не менять

Shared logger API, Telegram entrypoint, конфигурацию Compose и метаданные persistence.
