# Спецификация: совместимость NumPy/OpenCV в OCR

## Задача

Вариант OCR `full` устанавливает OpenCV 4.9.0.80 и без верхней границы получает NumPy 2.4.6. Эта бинарная сборка OpenCV ожидает NumPy 1.x ABI, поэтому импорт `cv2` падает; общий OCR перехватывает исключение, а `rupasportread` фактически пропускается.

## Решение

1. В общей базе зависимостей закрепить совместимую линию NumPy: `numpy>=1.26,<2`. Оставить существующий `opencv-python-headless==4.9.0.80` и OCR-код без изменений. Это минимальная совместимая правка: она устраняет подтверждённый ABI-конфликт, не меняя поведение OCR-библиотеки.
2. В full Docker image добавить сборочную smoke-проверку импорта `numpy`, `cv2` и `utils.rupasportread`. Несовместимый образ обязан завершать сборку ошибкой, а не запускать бота с незаметно отключённым OCR-модулем.
3. После успешной сборки пересоздать только `max_bot` (`docker compose up -d --no-deps max_bot`). Не запускать и не пересоздавать Telegram, PostgreSQL или migration: исправление не меняет их код, конфигурацию или схему БД.

## Решения по реализации

- Python 3.11 и текущие requirements/Docker Compose сохраняются.
- `requirements.txt` ограничивает NumPy ниже 2; причина — pinned OpenCV 4.9.0.80, который сейчас не поддерживает установленный NumPy 2.x ABI.
- Smoke-проверка находится в Dockerfile после копирования кода и установки full extras; light-вариант она не затрагивает.
- Регрессионный шов — реальная сборка варианта `full` и импорт фактического модуля OCR, а не тест-мок.
- Ошибка smoke-проверки блокирует deploy. Миграции БД не запускаются: схема не меняется.

## Границы и швы

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| `requirements.txt` | Ограничение совместимости Python-пакетов для обоих вариантов образа | Условие `numpy>=1.26,<2` | Конкретно выбранный pip-артефакт версии 1.x |
| `Dockerfile` (`full`) | Установка OpenCV/Tesseract и проверка импортов полного OCR-стека | Успешный full image либо ошибка сборки | Порядок и детали установки системных и Python-пакетов |

Тесты используют тот же import boundary: `numpy`, `cv2`, `utils.rupasportread` внутри full-образа.

## Вне рамок

- Переписывание/обновление `rupasportread`, изменение алгоритма распознавания или формата результата — не требуется для исправления ABI-конфликта (R01).
- Любой перезапуск или изменение Telegram, PostgreSQL и Alembic migration — не нужен для деплоя только MAX (R03).

## Открытые места

Нет. Для внешнего E2E OCR по фотографии не используется паспорт пользователя; проверяется импорт полного OCR-модуля и работоспособность процесса MAX.
